3. WHY BEHIND THE CHANGE
   - Argon2id Password Hashing: Winner of the Password Hashing Competition (PHC).
     Provides memory-hard protection against GPU/ASIC brute-force dictionary attacks,
     far superior to legacy hashing algorithms (bcrypt/MD5/SHA).
   - Dual-Token Model (Short-Lived Access + Opaque Refresh in httpOnly Cookies):
     Limits the exposure window of stolen JWTs to 15 minutes. Opaque refresh tokens
     stored in `httpOnly`, `Secure`, `SameSite=Strict` cookies prevent client-side XSS
     token exfiltration while enabling silent token rotation.
   - SHA-256 Hashing of Stored Refresh Tokens:
     Storing raw refresh tokens in the database exposes all active user sessions if the
     database is leaked. Storing one-way SHA-256 hashes ensures compromised database
     dumps cannot be used to impersonate active users.
   - TOTP MFA for Super Admin:
     Super Admin accounts possess destructive privileges (bulk roster deletion, fee
     waivers, system overrides). Mandatory Time-based One-Time Passwords (RFC 6238)
     enforce 2-Factor Authentication ("something you know" + "something you have"),
     neutralizing credential stuffing and phishing attacks without recurring SMS costs.

4. WHY NOT THE ALTERNATIVE(S)
   - Alternative 1: Bcrypt for Password Hashing
     * Why Rejected: While standard, Bcrypt is vulnerable to modern GPU/FPGA parallel
       attacks due to low memory utilization. Argon2id is the current industry gold standard.
   - Alternative 2: Long-lived single JWT stored in localStorage
     * Why Rejected: Insecure against XSS attacks; cannot be invalidated immediately
       upon logout or compromise without maintaining a heavy server-side token blacklist.
   - Alternative 3: SMS-Based 2FA OTP for Super Admin
     * Why Rejected: Vulnerable to SIM-swapping, dependent on cellular network coverage,
       and incurs external SaaS messaging costs (Twilio/AWS SNS). TOTP works 100% offline
       and securely on user devices.
