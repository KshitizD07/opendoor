3. WHY BEHIND THE CHANGE
   - ES Modules: Aligns the backend with the modern JavaScript/Node.js standard
     (consistent with frontend/React Native imports, future-proof, tree-shakeable).
   - Zod Environment Validation: Prevents silent runtime crashes by ensuring missing
     or invalid environment variables (secrets, ports, URLs) fail immediately on boot.
   - Centralized Error & Response Formatting: Enforces a uniform API response contract
     (`{ success: true/false, data, message, error }`) across all 11 modules.
   - `src/server.js` Entrypoint: Separating `app.js` (Express configuration) from
     `server.js` (HTTP transport, port binding, graceful shutdown) allows clean integration
     testing with Supertest without port binding conflicts.

4. WHY NOT THE ALTERNATIVE(S)
   - Alternative 1: CommonJS (`require` / `module.exports`)
     * Why Rejected: CommonJS is legacy in modern Node.js ecosystems. ES Modules
       provide unified syntax across client and server repositories.
   - Alternative 2: Unvalidated `process.env` access scattered across files
     * Why Rejected: Leads to runtime bugs when environment variables are missing
       or misconfigured in production.
   - Alternative 3: Ad-hoc `try/catch` with manual `res.status().json()` in every controller
     * Why Rejected: Causes inconsistent error payloads, code duplication, and leaked
       internal server errors to clients.
